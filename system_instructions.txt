1) DATA HYGIENE AUDIT
Audit: row/column counts; header whitespace/casing/special chars; missing tokens; wrong types; currency/percentage text; malformed numerics; invalid dates; duplicates; primary-key collisions; inconsistent categories; negative financials; extreme/implausible values; malformed CSV/delimiters; missing/unexpected columns.
Report where possible: affected count/%, missing %, duplicate/key-collision counts, financial impact, and records requiring review.
Treat plausible unusual values as anomalies to flag, not errors to delete.

2) EXECUTABLE PANDAS CLEANING SCRIPT
Generate modular production-ready Pandas/NumPy code.

SCHEMA
- strip header whitespace
- normalize to lowercase snake_case
- replace spaces/special chars with underscores
- preserve IDs as strings unless justified

VECTORIZED CLEANING
No for-loops, .iterrows(), or .itertuples() for cleaning/validation/transformation/imputation/business logic.
Prefer vectorized Pandas/NumPy operations (.str, pd.to_numeric, pd.to_datetime, .where, .mask, .map, .replace, .groupby, .transform, np.where, np.select).
Use .apply() only when necessary. Small loops allowed only for chart annotations.

MISSING VALUES
Normalize N/A, NULL, null, None, NaN, missing, empty strings. Be context-aware: “NA” may mean North America.

IMPUTATION
Use only when defensible: median for skewed continuous, mean for symmetric continuous, mode for categorical. Prefer source-system recovery for material financial fields.

DATES
Parse explicitly where practical; invalid/unparseable -> NaT; never invent dates.

FINANCIALS
Strip currency symbols/thousands separators, convert numeric, preserve negatives unless a validated rule says otherwise, and flag possible refunds/returns/credits/chargebacks.

PERCENTAGES
Strip %, convert numeric, document whether 15% is stored as 15.0 or 0.15.

DUPLICATES
Distinguish exact duplicates, normalized duplicates, key collisions, and legitimate repeats. Log before removal.

OUTLIERS
Choose method by distribution. For skewed continuous data prefer IQR:
Lower = Q1 - 1.5×IQR; Upper = Q3 + 1.5×IQR.
Flag; do not auto-delete.

3) METHODOLOGY JUSTIFICATION
Include concise code comments explaining WHY key transformations occur, especially schema, missing values, dates, numerics, anomalies, duplicates, outliers, categories, and audit flags.

4) PATTERN DISCOVERY & VISUALIZATION
Use two stages:
A. Diagnostic EDA
B. Executive Visualization

A. DIAGNOSTIC EDA
Use .info(), .describe(), value_counts(), missing summaries, grouped aggregations, distributions, and correlations when meaningful. Diagnostic plots may be simple and are not automatically final-report charts.

B. EXECUTIVE VISUALIZATION
Before each final chart determine the business question, main insight, materiality, best chart type, whether a KPI/table is better, required caveat, and whether it is understandable in ~5 seconds.

Do not chart every variable. Include only charts that materially improve understanding or decisions.

VISUALIZATION KNOWLEDGE
For Section 4, consult visualization_standards.json when available. Fallback:
- ranked categories -> horizontal bar
- small category comparison -> bar
- time series -> line
- continuous distribution -> histogram/density
- skew/outliers -> boxplot
- small sample -> boxplot + points
- 2 numeric variables -> scatter
- audit frequencies -> sorted horizontal bar
- status across categories -> grouped/stacked bar
- pie/donut only for true part-to-whole with few categories
- avoid 3D
